🔒 PILLAR 1: Advanced Cybersecurity

1.1 Zero-Trust Architecture (Data Diode Pattern)

What is it?

Zero-Trust means "never trust, always verify." In NEXUS, the LLM/intent parser is treated as an untrusted entity. It can only output a structured intent — it NEVER touches the database directly.

This is called the Data Diode Pattern: a strict one-way valve where the LLM outputs a typed payload, and a completely separate execution layer (that the LLM cannot control) decides what to do with it.

Why it matters

If the LLM parses intent AND queries the database, a prompt injection could force it to write a malicious query. By decoupling intent parsing from data access, even a fully compromised LLM cannot leak data.

How enterprise platforms do it

  • Snowflake: Uses Row-Level Security (RLS) and Column-Level Security (CLS) — access is enforced based on the user's token, not the service's token.
  • Databricks: Uses Unity Catalog with fine-grained ACLs at the table/column level.

NEXUS Implementation

from pydantic import BaseModel
from typing import Literal

# LLM can ONLY output this typed structure — nothing else
class SearchIntent(BaseModel):
    action: Literal["search_profiles", "count_profiles"]
    filters: dict

# The execution layer validates independently
@app.post("/search")
async def search(intent: SearchIntent):
    # LLM output is UNTRUSTED input — validate every field
    allowed_filter_keys = {"technology", "role", "location", "recent"}
    for key in intent.filters:
        if key not in allowed_filter_keys:
            raise HTTPException(403, "Unauthorized filter field")
    return execute_secure_search(intent.filters)

from collections import defaultdict
import time

request_log = defaultdict(list)
RATE_LIMIT = 10  # requests per minute

def check_rate_limit(client_ip: str) -> bool:
    now = time.time()
    request_log[client_ip] = [t for t in request_log[client_ip] if now - t < 60]
    if len(request_log[client_ip]) >= RATE_LIMIT:
        return False  # BLOCKED
    request_log[client_ip].append(now)
    return True

⛓️ PILLAR 2: Blockchain — Immutable Threat Ledger

2.1 How Blockchain Works (Simplified)

A blockchain is a linked list of blocks where each block contains a cryptographic hash of the previous block. This creates an unbreakable chain:

[Genesis Block] ←hash← [Block 1] ←hash← [Block 2] ←hash← [Block 3]

If any data in Block 1 is altered, its hash completely changes. But Block 2 still stores the OLD hash of Block 1. This mismatch proves tampering occurred. Every subsequent block also breaks.

Proof-of-Work

To "mine" a block, the system repeatedly hashes the block with an incrementing nonce until the hash starts with a specific number of zeros (the "difficulty"). For the hackathon, difficulty=2 (hash must start with 00) gives a satisfying mining delay (~100ms) without being slow.

2.2 Python Implementation

import hashlib, json, time

class Block:
    def __init__(self, index, event_type, event_data, previous_hash):
        self.index = index
        self.timestamp = time.time()
        self.event_type = event_type      # SECURITY_BLOCK, ALLOWED_QUERY, CHAT_START
        self.event_data = event_data
        self.previous_hash = previous_hash
        self.nonce = 0
        self.hash = self.calculate_hash()

    def calculate_hash(self):
        block_string = f"{self.index}{self.timestamp}{self.event_type}" \
                       f"{self.event_data}{self.previous_hash}{self.nonce}"
        return hashlib.sha256(block_string.encode()).hexdigest()

    def mine_block(self, difficulty):
        target = '0' * difficulty
        while self.hash[:difficulty] != target:
            self.nonce += 1
            self.hash = self.calculate_hash()

class ThreatLedger:
    def __init__(self):
        self.chain = [self._genesis()]
        self.difficulty = 2

    def _genesis(self):
        return Block(0, "GENESIS", "Nexus Threat Ledger Initialized", "0")

    def add_event(self, event_type, event_data):
        block = Block(
            index=len(self.chain),
            event_type=event_type,
            event_data=json.dumps(event_data),
            previous_hash=self.chain[-1].hash,
        )
        block.mine_block(self.difficulty)
        self.chain.append(block)
        return block

    def is_valid(self):
        for i in range(1, len(self.chain)):
            curr = self.chain[i]
            prev = self.chain[i - 1]
            if curr.hash != curr.calculate_hash():
                return False
            if curr.previous_hash != prev.hash:
                return False
        return True

2.3 Merkle Tree for Database Integrity

What is it?

A Merkle Tree is a binary tree of hashes. The leaves are hashes of individual developer profiles. Each parent node is a hash of its two children. The Root Hash at the top uniquely represents the entire dataset.

If a single byte changes in one profile, the Root Hash completely changes — detecting tampering instantly.

         [Root Hash]
        /           \
   [Hash AB]      [Hash CD]
   /      \       /      \
[Hash A] [Hash B] [Hash C] [Hash D]
   |        |        |        |
Profile1 Profile2 Profile3 Profile4

🔬 PILLAR 3: Quantum Computing — Post-Quantum Cryptography

3.1 The Quantum Threat

Shor's Algorithm

Current encryption (RSA, ECC, Diffie-Hellman) relies on problems that are impossible for classical computers: integer factorization and discrete logarithms. Shor's Algorithm (1994) can solve both in polynomial time on a quantum computer.

Harvest Now, Decrypt Later (HNDL)

This is why NEXUS should care NOW: - Nation-state actors are currently intercepting and storing encrypted internet traffic - When quantum computers arrive (estimated 2030-2035 per IBM/Google roadmaps), they will retroactively decrypt this hoarded data - Chat messages shared today could be exposed in 5-8 years

NIST Response

In August 2024, NIST finalized the first three Post-Quantum standards: - ML-KEM (CRYSTALS-Kyber) — Key Encapsulation - ML-DSA (CRYSTALS-Dilithium) — Digital Signatures - SLH-DSA (SPHINCS+) — Stateless Hash-Based Signatures

3.2 CRYSTALS-Kyber (ML-KEM) — Key Encapsulation

How Lattice Cryptography Works

Imagine solving A × s = b. Easy for computers. Now add random noise: A × s + e = b. This Learning With Errors (LWE) problem is so hard that even quantum computers cannot efficiently solve it.

How KEM Works (Like a Digital Lockbox)

  1. Alice generates a public/private key pair
  2. Bob generates a random symmetric key, encapsulates (encrypts) it using Alice's public key, sends the ciphertext
  3. Alice uses her private key to decapsulate (decrypt) and extract the shared secret
  4. Both now have the same AES-256 key for symmetric encryption

Parameter Sets

Variant Security Level Key Size Best For
Kyber-512 ~AES-128 800 bytes Hackathon demo (fast)
Kyber-768 ~AES-192 1,184 bytes Recommended default
Kyber-1024 ~AES-256 1,568 bytes Maximum security

Python Implementation Options

  • Real: liboqs-python (industry standard, needs C library)
  • Pure Python: kyber-py by GiacomoPope (perfect for hackathon — no native dependencies)
  • Simulation: Generate realistic-looking hex values and demonstrate the flow conceptually

3.3 CRYSTALS-Dilithium (ML-DSA) — Digital Signatures

While Kyber establishes a secure channel, Dilithium ensures authenticity — proving the person you're chatting with is really who they claim to be.

NEXUS Implementation

  1. Every user gets a Dilithium keypair
  2. When Alice sends a chat message, her client signs the message with her private key
  3. Bob's client verifies the signature using Alice's public key
  4. If verification fails → the message is flagged as potentially forged

3.4 Hybrid Encryption (Classical + PQC)

Why Hybrid?

PQC algorithms are new. There's a small chance a mathematical flaw could be found. The solution: combine classical + PQC encryption. Even if one breaks, the other holds.

How Signal Does It (PQXDH)

3.5 ⭐ BB84 Quantum Key Distribution Simulation

What is it?

BB84 uses quantum mechanics (not math) for security. Individual photons carry key bits. Because measuring a quantum state changes it (Heisenberg's Uncertainty Principle), any eavesdropper is physically detectable.

How BB84 Works

  1. Alice sends photons in random polarization bases (Rectilinear ⬆️➡️ or Diagonal ↗️↘️)
  2. Bob measures each photon in a random base
  3. They publicly compare which bases matched (not the values!)
  4. Matching bases = shared secret key
  5. If an eavesdropper (Eve) intercepted, the error rate exceeds 25% → channel compromised

React Visualization

  • Animated glowing dots (photons) traveling between Alice and Bob
  • Bases shown as icons (⬆️/➡️ for Rectilinear, ↗️/↘️ for Diagonal)
  • "Simulate Eavesdropper" button → Eve appears on the line → error rate spikes → "QUANTUM TAMPERING DETECTED"
